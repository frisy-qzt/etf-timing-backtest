# 代码规范

## 自动化基线

Python ≥ 3.10，UTF-8、LF、4 空格缩进、双引号，目标行宽 100。Ruff 版本固定在 `pyproject.toml` 的 dev extra；格式化器可能保留不可拆分的长字符串。启用 E4/E7/E9、F 和 I，覆盖导入、明显错误和常见 Python 问题。历史脚本需要先设路径再导入的 E402 例外逐文件列出，不对包源码放开。

```bash
python -m ruff check .
python -m ruff format --check .
# 修改后主动规范化；检查 diff 再提交
python -m ruff check --fix .
python -m ruff format .
```

本轮只做机械格式化、导入规范化和明确的未用绑定清理，避免同时重写回测逻辑。新代码应为公开接口添加参数与返回类型，说明 DataFrame 字段、单位、索引和副作用。既有动态 DataFrame 接口尚未实施全仓严格静态类型检查，不声称已通过 mypy。

## 行为约束

- 优先清晰的小函数和显式参数；领域口径变更必须单独解释，不能混入格式化。
- 信号、成交价格、估值价格分离；当前窗口信息不得决定此前订单。
- 输入不合法时抛出明确的 `ValueError` / `TypeError`；不静默填造数据。
- 新文件使用 UTF-8；新写报告通过临时文件和原子替换保护旧结果。
- 无导入时的数据读取、网络请求或长任务；脚本入口使用 `main()` 和标准入口保护。
- 核心包不引入本机绝对路径、凭据或可选离线依赖目录。
- 中文解释经济口径，英文标识符保持一致；注释解释原因，不复述代码。

## 测试原则

沿用 `unittest`，普通测试使用合成数据和临时目录。行为修改先添加可重现失败的案例，再做最小修复。账本用手工可核算的金额与时间断言；因果信号用前缀不变性验证。真实行情验收不替代单元测试，也不作为公开 CI 的隐形依赖。
